## The one thing you must know

**Two eras, two sources of truth.**

1. **Migration era (local `master`; remote `fidelity-baseline-2026-09`).**
   The original Next.js site is gone; its content survives only as **SSR
   HTML snapshots** in the sibling repo
   `../kossoko-africa-mining-montreal-2026` (the "legacy clone"). That repo
   is archived on its `legacy-clone-2026` branch — keep it checked out
   there so `tools/check-fidelity.mjs` can keep reading `src/snapshots/`.
   This project rebuilt those snapshots verbatim as React components —
   that work is complete and frozen.
2. **Client-changes era (branch `main`, promoted 2026-09-09).** The client's
   change requests of **2026-09-08** (`docs/New-Changes-Sept-8-2026/` —
   `Website_comments.docx` + LAYOUT screenshots, not committed: ~27 MB)
   **supersede snapshot fidelity**. Roughly 50 changes were applied in
   nine dated commits (512081c…2567b8e). The docx is the design authority
   for everything it covers; the snapshots remain the authority for
   everything it doesn't.

**Repository layout (since 2026-09-09).** The canonical remote is
`github.com/asaklex/kossoko-africa-mining-montreal-2026` (this repo's
`origin`). Branches there: `main` = the living client era; `fidelity-baseline-2026-09`
= the frozen migration; `legacy-clone-2026` (+ tag `legacy-2026-final`) =
the previous dev's clone, kept for its SSR snapshots; `perfect-copy` and
`feature/reactable` are redundant older duplicates of that clone.

Consequences:

- **Never try to fetch the reference origin** (`a2m-website-git...vercel.app`)
  — it is dead. Its URL survives only in intentionally dead links (`fr`
  buttons, the program PDF).
- **The client changes his mind often.** Work in small, dated, revertible
  commits; one logical change set per commit; quote the request in the
  commit message.
- **Preserve class strings** — they are the design system in action, not
  noise. Do not "clean up" or reformat classes into fragments; partial
  class names won't be generated by Tailwind.
- `tools/check-fidelity.mjs` still diffs against the snapshots, but on the
  client-changes branch the diff is expected to be large on every page the
  docx touched. Use it only to answer "did *I* change something beyond
  what was requested", not as a pass/fail gate. The gate is
  `npm run build` + browser sanity of the affected routes.
- The 2026-09-08 divergence registry lives in
  `docs/migration-and-fidelity.md` → *Client changes (2026-09-08)*.

## Commands

```bash
npm run dev        # dev server (http://localhost:5173)
npm run build      # tsc (strict) + vite build → dist/
npx vite preview --port 4173   # serve the production build
node tools/check-fidelity.mjs extract   # pull snapshots from the legacy repo → /tmp/a2m-snapshots
node tools/check-fidelity.mjs snapshot  # canonicalize snapshots → /tmp/a2m-rendered/*.expected.txt
node tools/check-fidelity.mjs diff      # compare *.actual.txt dumps against expected
```

`npm run build` is the gate: TypeScript is strict with `noUnusedLocals` /
`noUnusedParameters`, so **remove imports when you delete code**.

## Verification loop (after any visual/DOM change)

1. `npm run build`
2. `npx vite preview --port 4173` (background)
3. Regenerate expected: `extract` + `snapshot` modes above (needs the legacy
   repo at `../kossoko-africa-mining-montreal-2026`, or set `A2M_LEGACY_REPO`).
4. Capture actual: for each of the 13 routes in `tools/check-fidelity.mjs`
   (ROUTES), load `http://localhost:4173<route>` in a browser and run the
   canonicalizer from the tool (`CANONICALIZER_SOURCE`, exported) against
   `document.body`, saving to `/tmp/a2m-rendered/<route-slug>.actual.txt`.
   With the ZCode in-app browser the whole loop is ~30 lines of JS in the
   node REPL (see `docs/migration-and-fidelity.md` → *Capturing the rendered
   side*).
5. `node tools/check-fidelity.mjs diff` — compare against the **current
   baseline** below: every page carries exactly 48 header-only diff lines
   from the dropdown controller; anything beyond that table is a regression
   you introduced.
6. For CSS coverage after class changes: collect `classList` tokens from the
   rendered pages into `/tmp/a2m-rendered/all-classes.json`, then
   `node tools/check-classes.mjs` — every token must resolve in
   `dist/assets/*.css`.

### The Tabs component contract (important)

`src/components/ui/Tabs.tsx` reproduces the reference site's three tab
families. Pages pass **full class strings and both trigger variants**:

- `triggerClassActive` / `triggerClassInactive` — the reference shipped
  *different class strings per state* (colours on inner spans too), so items
  carry `triggerActive` / `triggerInactive` JSX variants. Don't merge them.
- `listWrapperClassName` / `listPreamble` — the "Mission / How it works"
  layouts wrap the tablist in a `div.relative` with decorative timeline
  rails; the preamble JSX is those rails.
- `panelContainerClassName` — sidebar layouts (pillars, conference themes)
  wrap all panels in a `min-w-0` column.

## Editing rules (learned the hard way)

1. **No `sed` / regex batch edits over `src/pages/*.tsx`.** They are huge
   (up to ~150 kB) machine-migrated files; a blind replace once introduced
   an infinite recursion that crashed the app at mount *silently*. Use
   targeted edits, then rebuild.
2. **If a page renders blank/empty `<div id="root">`**, suspect a thrown
   effect or render error: React 19 unmounts the whole tree. Check the
   browser console; recent culprits have been batch edits (see rule 1).
3. **Tailwind v4 generates utilities by scanning source text.** Class
   strings extracted as data (Tabs props, NewsFilter cards) are in the
   source, so they compile. If you compose classes dynamically
   (`` `w-${size}` ``), they won't exist — always write complete class names.
4. **lucide-react's current icon set differs slightly from the original
   build's.** When an icon's paths must match exactly, inline the original
   SVG (precedent: `CalendarDays` inside `HeroCarousel.tsx`).
5. `tools/snapshot-to-jsx.mjs` regenerates `src/pages/*.tsx` — running it
   **overwrites manual page edits**. It exists for provenance/re-runs; only
   use it deliberately, then re-apply hand changes (see
   `docs/migration-and-fidelity.md` → *Regenerating pages*).
6. Behaviour restorations are features, not drift: the header dropdown
   controller (hover intent, close on nav/Escape), the working news filter,
   KPI scroll animations, scroll-spy "On this page" nav. Keep them.
